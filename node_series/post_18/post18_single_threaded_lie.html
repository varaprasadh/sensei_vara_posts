worker_threads —
same process, real threads

Same process. Separate V8 isolates. Share memory via SharedArrayBuffer. Best for CPU-bound JS: parse, hash, compress, transform.

const { Worker, isMainThread, parentPort } =
    require('worker_threads');

if (isMainThread) {
  const w = new Worker('./worker.js');
  w.on('message', result => console.log(result));
  w.postMessage({ data: bigInput });
} else {
  parentPort.on('message', ({ data }) => {
    parentPort.postMessage(heavyTransform(data));
  });
}

Event loop stays unblocked. Worker runs on another core.

$ # escape hatch #2

cluster —
multi-core HTTP server

Forks one Node process per CPU. OS round-robins incoming connections. Each worker is a full Node process — no shared memory, separate heap. Best for: scaling HTTP throughput.

const cluster = require('cluster');
const { cpus } = require('os');

if (cluster.isPrimary) {
  cpus().forEach(() => cluster.fork());
  cluster.on('exit', (w) => cluster.fork()); // auto-restart
} else {
  // each worker listens on SAME port
  require('./server').listen(3000);
}

8 cores → 8 workers. No code changes to your HTTP handlers.

child_process —
run anything

spawn/exec/fork. Run another binary, shell command, or Node script. Communicate via stdin/stdout or send()/on('message'). Best for: external tools, crashy isolation.

const { spawn, fork } = require('child_process');

// run any binary
const proc = spawn('ffmpeg', ['-i', 'in.mp4', 'out.webm']);
proc.stdout.on('data', d => process.stdout.write(d));

// or fork another Node script (gets send/message IPC)
const child = fork('./risky-task.js');
child.send({ job: payload });
child.on('message', result => handle(result));
child.on('exit', code => log(`exited ${code}`));

Crash in child? Parent survives. Natural isolation boundary.

$ # see it yourself

Fib off-thread.
Loop never blocks.

const { Worker, isMainThread, parentPort, workerData } =
    require('worker_threads');

function fib(n) { return n <= 1 ? n : fib(n-1) + fib(n-2); }

if (isMainThread) {
  let ticks = 0;
  const interval = setInterval(() => process.stdout.write(`tick ${++ticks}\n`), 100);
  const w = new Worker(__filename, { workerData: 44 });
  w.on('message', r => { clearInterval(interval); console.log(`fib(44) = ${r}`); });
} else {
  parentPort.postMessage(fib(workerData));
}
$ node fib_worker.js
tick 1   ← main thread ticking while worker computes
tick 2
tick 3
...
tick 11
fib(44) = 701408733   ← worker done, ~1.1s later

Without worker: zero ticks — event loop frozen for entire 1.1s.

Quick recap

  • single-thread = JS only. libuv threads are hidden.
  • worker_threads — CPU-bound JS. Same process. Share SAB.
  • cluster — scale HTTP. Multiple processes, one port.
  • child_process — external bins. IPC or stdio. Crash isolation.
  • Shared state → SharedArrayBuffer (workers) or messages
