$ # the thing nobody tells you

Top-level code runs
ONCE.
Whether you want it to or not.

Call require('./db') from 12 different files. Node executes db.js exactly once.

Every subsequent require gets the cached module.exports — same object, same reference.

Side effects? Singletons? Mutations? They all follow from this one rule.

One log. Three
requires.

// counter.js
console.log('loaded')        // runs ONCE, ever
module.exports = { count: 0 }

// app.js
const a = require('./counter')   // prints "loaded"
const b = require('./counter')   // silent — cache hit
const c = require('./counter')   // silent — cache hit

a.count++                         // a, b, c are the SAME object
console.log(b.count)              // → 1  (mutation visible everywhere)
console.log(a === b)              // → true

"loaded" prints once. a === b === c — same reference. Mutate one, all see it.

$ # when this is a feature

One instance.
Whole app.

DB pools, config, loggers — all exploit the cache to share one object everywhere.

// db.js — create the pool ONCE
const { Pool } = require('pg')
module.exports = new Pool({ max: 10 })    // singleton

// routes/users.js
const db = require('../db')    // same pool

// routes/orders.js
const db = require('../db')    // same pool — no new connection

// config.js — loaded once, shared everywhere
module.exports = Object.freeze(require('./config.json'))

Good when intentional. You get 10 connections, not 10 pools of 10.

$ # the footgun

Tests that mutate
inherit state.

// counter.js
module.exports = { count: 0 }

// test A — passes
const c = require('./counter')
c.count = 99                       // ← mutates the shared object

// test B — runs in same process, same cache
const c2 = require('./counter')
console.log(c2.count)              // → 99  💥 not 0

// fix: clear cache before re-requiring
delete require.cache[require.resolve('./counter')]
const fresh = require('./counter')  // fresh module, count = 0

Red = the bug. Green = clear cache → reload → clean state.

$ # see it yourself

Inspect the cache
live.

Drop this in any Node project. Watch the cache grow.

// paste into Node REPL or a .js file
console.log(Object.keys(require.cache).length)
// → 0  (nothing loaded yet)

require('path')
require('fs')
require('os')

console.log(Object.keys(require.cache).length)  // → 3
console.log(Object.keys(require.cache)[0])       // absolute path

// require same module twice — count stays 3
require('path')
console.log(Object.keys(require.cache).length)  // → still 3

Keys are absolute resolved paths — that's how Node deduplicates.

Quick recap

  • Cache keyed by resolved path — same file = same entry
  • Top-level code runs exactly once — ever
  • Mutate module.exports → all importers see it
  • delete require.cache[...] to force fresh reload in tests
  • ESM has no require.cache — use import(url + '?v=' + Date.now())
