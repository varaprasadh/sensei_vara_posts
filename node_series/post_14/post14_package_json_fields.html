exports
03 / 08
$ # public API surface

exports — controls
entry points.

Replaces main. Supports conditional import/require/types. Hides internals.

"exports": {
  ".": {
    "import":  "./dist/index.mjs",
    "require": "./dist/index.cjs",
    "types":   "./dist/index.d.ts"
  },
  "./utils": "./dist/utils.js"
}

Without exports: consumers can import your internal files. With it: only the surface you expose.

types
04 / 08
$ # TypeScript entry point

types — points TS
to your .d.ts.

Without it, TypeScript users import your package and get any. That's worse than no types.

// package.json
"types": "./dist/index.d.ts"

// OR inside "exports" per-condition:
".": {
  "types":   "./dist/index.d.ts",
  "import":  "./dist/index.mjs",
  "require": "./dist/index.cjs"
}

Rule: types entry inside each export condition wins over top-level types.

sideEffects
05 / 08
$ # bundler tree-shaking hint

sideEffects: false
→ drop dead code.

Tells webpack/rollup/esbuild: every module is pure. Unused imports = deleted. No guessing.

"sideEffects": false                   // whole pkg is pure
// or list files that DO have side effects:
"sideEffects": ["./src/polyfills.js"]

Bundle impact (real example — utility lib):

200 KB — no sideEffects flag
30 KB — sideEffects: false
−85%

engines
06 / 08
$ # version gate

engines — min
Node version.

npm/yarn warn on mismatch. Add .npmrc engine-strict=true → hard fail. Catches "works on my machine".

"engines": {
  "node": ">=18.17"
}

// .npmrc
engine-strict=true
npm install → ❌ warn + engine-strict → ❌ fail

No engines field = someone installs on Node 14 and gets a cryptic runtime crash.
