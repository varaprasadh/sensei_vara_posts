Why does Promise.then
always beat setTimeout(fn, 0)?

Both are async. Both are "immediate". One always wins.

setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));

// Output:
// promise    <— always first
// timeout    <— always second

Not a race condition. Not a quirk. By design.

Different queues. Different priorities.

$ # the footgun

Infinite microtasks
starve everything else.

function infinitePromise() {
  Promise.resolve().then(infinitePromise);  // ← starvation
}

infinitePromise();

// setTimeout never fires
setTimeout(() => console.log('never'), 0);  // ← starved

// setImmediate never fires either
setImmediate(() => console.log('also never'));  // ← starved

Microtask queue drains before any macrotask. Infinite chain = macrotasks blocked forever.

Real-world shape: recursive async loops without await on I/O.
