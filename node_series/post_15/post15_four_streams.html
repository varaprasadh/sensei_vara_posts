$ # what most devs miss

You use streams.
You don't know you do.

Most Node devs only touch streams via .pipe(). There are 4 stream classes — each with a specific job.

Readable → Writable
Duplex + Transform

Every http.req, every fs.createReadStream, every zlib.createGzip — all streams. You're already using them.

All event-driven: data / end / error.

Readable — data source.

const fs = require('fs');

const src = fs.createReadStream('big.log');

src.on('data', chunk => process.stdout.write(chunk));
src.on('end',  () => console.log('done'));
src.on('error', err => console.error(err));

Also: http.IncomingMessage (request body), process.stdin.

dest.on('finish', () => console.log('written'));

Duplex — read AND write.

const net = require('net');

// TCP echo server — socket is Duplex
net.createServer(socket => {
  socket.pipe(socket);  // read + write same stream
}).listen(3000);

One object. You read from it. You write to it. Independent channels.

$ # see it yourself

3 streams. One chain.

const fs   = require('fs');
const zlib = require('zlib');

// read → transform → write
fs.createReadStream('input.txt')    // Readable
  .pipe(zlib.createGzip())           // Transform
  .pipe(fs.createWriteStream('output.gz')); // Writable
Readable

.pipe()
Transform

.pipe()
Writable

.pipe() wires Readable output → Writable input. Data flows chunk by chunk — never all in memory.

$ # tl;dr

Quick recap

  • Readable — source. data flows out. fs.createReadStream
  • Writable — sink. data flows in. fs.createWriteStream
  • Duplex — both ends. net.Socket
  • Transform — bidi + modify. zlib.createGzip
  • .pipe() — connect them. chunk by chunk.
