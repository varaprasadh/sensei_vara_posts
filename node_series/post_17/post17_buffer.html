$ # if you've done streams, you've met Buffer

That weird
chunk.length.

You log chunk.length from a stream. You expected the number of characters. You got something else.

// readable stream on a file
stream.on('data', (chunk) => {
  console.log(typeof chunk);       // "object"
  console.log(chunk.length);     // bytes, not chars
});

That chunk isn't a string. It's a Buffer. And .length counts bytes, not characters.

$ # what Buffer actually is

Uint8Array
subclass. Fixed bytes.

Not a JS string. A fixed-length sequence of raw bytes. Chars ≠ bytes for multi-byte encodings.

"héllo" = 5 chars. UTF-8 encoded = 6 bytes. 'é' takes 2 bytes.

$ # encoding changes everything

Same bytes.
Different lens.

const buf = Buffer.from('hi');

buf.toString('utf8')    // → "hi"
buf.toString('hex')     // → "6869"
buf.toString('base64')  // → "aGk="
buf.toString('latin1')  // → "hi"

Same buffer. Four representations. Bytes don't change — the encoding is just how you read them.

utf8 hex base64 latin1 binary ascii

$ # alloc vs allocUnsafe

Faster ≠ safer.

// zeroed — always safe to ship
const safe = Buffer.alloc(10);
// <Buffer 00 00 00 00 00 00 00 00 00 00>

// NOT zeroed — reuses memory slab
const fast = Buffer.allocUnsafe(10);
// may contain: previous memory contents!
// eg: <Buffer 68 65 6c 6c 6f 20 77 6f 72 6c>
//  ← leftover "hello wor" from prior op

// DANGER: ship this over network = data leak
allocUnsafe is fine IF you fill before sending. Zero-fill with alloc() when in doubt.

$ # where Buffers actually live

Not on the
V8 heap.

Buffer memory is C++-managed. The GC doesn't touch it. That's why large file transfers don't blow up your JS heap.

Big file? Stream it as Buffers. V8 GC stays clean. No pause.

const str = 'héllo';

console.log(str.length);          // 5  ← chars

console.log(buf.toString('hex'));
// 68c3a96c6c6f
// ^^   'h'
//   ^^^^  'é' (2 bytes: c3 a9)
//       ^^^^^^^^  'llo'

String length = Unicode code points. Buffer length = actual bytes on wire. They diverge the moment you leave ASCII.

$ # tl;dr

Quick recap

  • Buffer = fixed-length byte sequence (Uint8Array subclass)
  • encoding matters — utf8, hex, base64, latin1 all differ
  • alloc() safer than allocUnsafe() — zero-fill costs little
  • off-heap — C++ memory, not GC'd, huge transfers stay cheap
  • streams hand you Buffers, not strings — decode explicitly
