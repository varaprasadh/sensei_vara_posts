$ # rule 1 of 4

return 42
= Promise<42>

JS auto-wraps with Promise.resolve(). Caller MUST .then() or await to get 42.

async function fn() {
  return 42;        // JS wraps → Promise.resolve(42)
}

const p = fn();
console.log(p);    // Promise { 42 }  ← NOT 42
// to get 42:
p.then(v => console.log(v)); // 42

$ # rule 2 of 4

throw = rejected
Promise

No uncaught exception. The error becomes a rejection. You handle it with .catch() or try/await.

async function fn() {
  throw new Error('something broke');
}

fn().catch(err => console.log(err.message));
// → 'something broke'

// without .catch():
fn();  // UnhandledPromiseRejection ← next post

Sky note: skip the .catch() → unhandled rejection trap. Next post.

05 / 08
$ # rule 3 of 4

Return a Promise?
No double-wrap.

Async + returning a Promise doesn't nest them. JS flattens it. Promise<Promise<5>> is never a thing.

async function fn() {
  return Promise.resolve(5); // returns a Promise
}

fn().then(v => console.log(v)); // → 5, not Promise{5}
^ result is Promise<5>, not Promise<Promise<5>>

This is called Promise flattening (or "assimilation"). Async inherits it from .then().

$ # rule 4 of 4

await needs
an async context

// BAD — SyntaxError
function sync() {
  const x = await fetch('/api'); // ✗ SyntaxError
}

// GOOD — works
async function good() {
  const x = await fetch('/api'); // ✓
}

// ESM top-level await (.mjs or "type":"module")
const data = await fetch('/api'); // ✓ ESM only

The fix is always the same: make the caller async too. This is "async creep" — it spreads up the call chain.

$ # tl;dr

Quick recap

  • async = auto Promise wrap, always
  • return x = Promise.resolve(x)
  • throw err = Promise.reject(err)
  • return Promise = no double-wrap (flattened)
  • await only inside async (or ESM top-level)
  • "async creep" — async spreads up the call chain
