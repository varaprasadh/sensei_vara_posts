$ # the problem most devs never see coming

RAM eater hiding
in plain sight.

Backpressure is what stops your Node process from eating all the RAM when you copy a big file the wrong way.

Your Readable produces data at full disk speed.
Your Writable flushes to a slow network socket.

Gap between them? That gap lives in your heap.

fast Readable →→→ heap buffer → slow Writable

The missing signal: .write() returns false when full.

$ # the code that kills your server
BAD — bypasses backpressure

Ignoring
.write()
return value.

const fs = require('fs');

const readable = fs.createReadStream('huge.bin');
const writable = fs.createWriteStream('out.bin');

readable.on('data', chunk => writable.write(chunk)); // ← ignores backpressure

.write() returns false when buffer is full.
You never check it. Heap balloons. Eventually: OOM crash.

$ # .pipe() — backpressure for free
GOOD — backpressure handled

.pipe()
does it for you.

const fs = require('fs');

const readable = fs.createReadStream('huge.bin');
const writable = fs.createWriteStream('out.bin');

readable.pipe(writable); // pauses source when sink is full

When .write() returns false, pipe pauses the Readable.
Resumes on 'drain' event. Memory stays flat.

But: no error handling. One stream errors → silent leak.

$ # the production answer
BEST — backpressure + errors + cleanup 
const { pipeline } = require('stream/promises');
const zlib = require('zlib');
const fs = require('fs');

await pipeline(
  fs.createReadStream('huge.bin'),
  zlib.createGzip(),
  fs.createWriteStream('out.bin.gz')
); // throws on error, cleans up all streams

// this is the production answer.

Backpressure: yes. Error propagation: yes. Cleanup on failure: yes.
All three in one call.

$ # see the heap difference yourself

Watch RSS
balloon vs flat.

const { pipeline } = require('stream/promises');
const fs = require('fs');

// BAD: manual data → heap grows
const bad = () => {
  const r = fs.createReadStream('/dev/urandom', { end: 1e9 });
  const w = fs.createWriteStream('/dev/null');
  r.on('data', c => w.write(c)); // RSS: grows → OOM
  setInterval(() => console.log(process.memoryUsage().rss), 500);
};

// GOOD: pipeline → constant memory
const good = async () => {
  await pipeline(fs.createReadStream('/dev/urandom',{end:1e9}),
                 fs.createWriteStream('/dev/null')); // RSS: flat
  setInterval(() => console.log(process.memoryUsage().rss), 500);
};

bad(): rss climbs → crash  |  good(): rss stays ~30MB

Quick recap

  • slow sink + fast source = heap balloon → OOM
  • .write() returns false when buffer is full — that's the signal
  • .pipe() handles pause/resume automatically
  • pipeline() = backpressure + error propagation + cleanup
  • never use manual 'data' handler without checking return value
