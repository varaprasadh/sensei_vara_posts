// what most devs get wrong

One queue.
Wrong.

If you think the event loop is a single queue pulling callbacks — that's why this surprises you:

setTimeout(function() {
  console.log('timeout');
}, 0);

setImmediate(function() {
  console.log('immediate');
});

// Output can be EITHER order depending on
// where in the loop you are. Not a bug. A phase.

The event loop has 6 distinct phases. Each runs its own queue. Order matters.

// the 3 phases you actually hit

Three phases.
99% of your code.

// ① TIMERS phase
setTimeout(() => console.log('A'), 0);     // ← fires here

// ④ POLL phase  (I/O callbacks)
fs.readFile('./data.json', (err, buf) => {
  console.log('B');                        // ← fires here
});

// ⑤ CHECK phase
setImmediate(() => console.log('C'));    // ← fires here
① timers → ④ poll → ⑤ check

Phases ②③⑥ exist. You rarely schedule into them directly.

// between every phase

Microtasks don't wait
for the next phase.

Order: nextTick drains first, then Promise microtasks, then next phase starts.

Starve the microtask queue → block the loop. Don't recurse nextTick.

The output will
surprise you.

setTimeout(() => console.log('① setTimeout'), 0);
setImmediate(() => console.log('② setImmediate'));
Promise.resolve().then(() => console.log('③ Promise'));
process.nextTick(() => console.log('④ nextTick'));
console.log('⑤ sync');

// ─── Output ───────────────────────────────
⑤ sync          // call stack runs first
④ nextTick       // nextTick drains before promises
③ Promise        // microtask queue
// ↑ BOTH drain before ANY macro phase
① setTimeout     // timers phase (may swap with ②)
② setImmediate   // check phase

nextTick + Promise always beat timers. Always. That's microtask drain.

// tl;dr

Quick recap

  • 6 phases — timers → pending → idle → poll → check → close
  • each phase has its own queue. Not one queue.
  • microtasks (nextTick + Promise) drain between every phase
  • nextTick drains before Promise. Queue jumper.
  • poll is where I/O waits. Node blocks here intentionally.
