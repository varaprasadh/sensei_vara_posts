$ # what most devs assume

One log line.
20% slower API.

A console.log in your hot path can slow your API by 20%. Most devs think it's free.

app.get('/users', async (req, res) => {
  console.log('GET /users', req.query);  // ← killer
  const users = await db.query('SELECT * FROM users');
  res.json(users);
});

This runs on every request. At 1k req/s, that's a lot of blocked I/O.

$ # gotcha #1 — deep clone

Stop cloning
with JSON.parse.

Slow. Loses Date, Map, Set, undefined. Throws on circular refs.

// BAD — expensive + lossy
const clone = JSON.parse(JSON.stringify(obj));
// Date → string, Map → {}, Set → {}
// GOOD — Node 17+, native C++, handles it all
const clone = structuredClone(obj);
// preserves Date, Map, Set, ArrayBuffer...

structuredClone is ~2–5× faster on large objects. Built-in since Node 17.

$ # gotcha #2 — regex in loops

Regex compiles
every iteration.

JS engines recompile regex literals inside loops. Hoist it out.

// BAD — recompiled N times
for (const s of items) {
  if (s.match(/foo_\d+/)) { ... }  // ← bad
}
// GOOD — compiled once, reused
const re = /foo_\d+/;
for (const s of items) {
  if (re.test(s)) { ... }  // fast
}

Also: .test() is faster than .match() when you only need a bool.

$ # gotcha #3 — new Date() in hot paths

new Date() costs.
Use Date.now().

Each new Date() allocates an object on the heap. Adds up fast in hot loops.

new Date()
→
heap alloc + GC pressure
→
~µs × 1M = real ms
Date.now()
→
returns a number
→
no alloc, fast
// BAD — allocates object every call
const ts = new Date().getTime();

// GOOD — number, no GC
const ts = Date.now();

$ # fix — use pino

Replace console.log
with pino.

Pino batches writes, formats async, emits NDJSON. Way cheaper.

import pino from 'pino';
const log = pino();

// async, batched, structured
log.info({ userId: 42 }, 'GET /users');

Drop-in swap. Structured logs → searchable in Datadog / CloudWatch. No excuses.
