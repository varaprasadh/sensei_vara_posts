-- the myth

Normalization is
supposedly hard.

It's actually three rules. Most schemas need only the first three forms. That's it.

1NF
→
2NF
→
3NF
→
BCNF, 4NF, 5NF…

Each form adds one constraint on top of the previous. Devs overthink it. You don't need BCNF for a blog.

Stop at 3NF. Denormalize only when the query plan forces you.

1nf.sql
03 / 08
-- first normal form

1NF — atomic values.
No arrays-in-a-column.

✗ BAD
-- tags crammed in one string
CREATE TABLE posts (
  id      BIGINT PRIMARY KEY,
  title   TEXT,
  tags    VARCHAR(200)
  -- "db,sql,index"
);
✓ GOOD
-- proper array column + GIN
CREATE TABLE posts (
  id      BIGINT PRIMARY KEY,
  title   TEXT,
  tags    TEXT[]
);
CREATE INDEX ON posts
  USING GIN(tags);

Or: a separate post_tags(post_id, tag) table if you need tag-level queries. Either way — no CSVs in columns.

04 / 08
-- second normal form

2NF — whole-key
dependency.

Composite key (order_id, product_id) → every non-key column must depend on the whole key.

qty stays — it depends on the full pair. product_name goes — it only needs product_id.

05 / 08
-- third normal form

3NF — no transitive
dependency.

Non-key columns must depend on the key, not on each other.

country depends on zip, not on user.id. That's a transitive dep — extract it.

06 / 08
-- the honest tradeoff

Fully normalized =
more joins.

Sometimes that's fine. Hot-path reads? Break the rule. Deliberately.

-- normalized: join every time
SELECT p.title, u.name AS author
FROM  posts p
JOIN  users u ON u.id = p.user_id
WHERE p.id = 42;

-- denormalized: author_name stored on posts
SELECT title, author_name FROM posts WHERE id = 42;
-- single PK lookup. zero joins.

The cost: author_name can drift if users rename. Acceptable? Your call. Make it intentional, not accidental.

07 / 08
-- see it yourself

Messy → 3NF.
Side by side.

✗ before (1 big table)
CREATE TABLE blog (
  id          BIGINT PK,
  title       TEXT,
  author_name TEXT,
  author_email TEXT,
  tags        VARCHAR(500),
  cat_id      INT,
  cat_name    TEXT
);
✓ after (3NF)
CREATE TABLE users (
  id    BIGINT PK,
  name  TEXT, email TEXT
);
CREATE TABLE categories (
  id   BIGINT PK, name TEXT
);
CREATE TABLE posts (
  id       BIGINT PK,
  title    TEXT,
  user_id  BIGINT REFERENCES users,
  cat_id   BIGINT REFERENCES categories,
  tags     TEXT[]
);

08 / 08
-- tl;dr

Quick recap

  • 1NF — atomic values. no arrays-in-a-column.
  • 2NF — every non-key col depends on the whole key.
  • 3NF — non-key cols don't depend on each other.
  • Normalize first. Denormalize only on measured read pressure.
  • BCNF/4NF/5NF — diminishing returns. Stop at 3.
