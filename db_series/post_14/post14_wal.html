-- # the puzzle

COMMIT returns
in 1 ms.

A full disk fsync of a data page would take 100× longer.
So… how?

Postgres doesn't fsync the page on COMMIT.
It fsyncs the WAL instead.
WAL = Write-Ahead Log.
A sequential append-only file that records every change before it hits the heap.

06 / 08
-- # WAL does more than durability

WAL is also
your superpower.

Durability is just the start. The same log file enables two more killer features.

🔁
Streaming Replication
Primary ships WAL records to replica in real time. Replica replays them. Zero extra overhead — same log you already write.
⏪
Point-in-Time Recovery
Archive WAL + base backup. Replay up to any LSN or timestamp. Dropped a table at 3 PM? Restore to 2:59 PM.

-- # tl;dr

Quick recap

  • WAL — changes appended to log before pages are flushed
  • COMMIT — fsyncs WAL only, not the heap page
  • sequential — WAL appends fast; random page writes happen later
  • crash → replay — replay WAL from last checkpoint → consistent
  • replication + PITR — both ship or archive the same WAL stream
