vacuum_full.sql 13 / 20
// two modes — know the difference

VACUUM vs VACUUM FULL

VACUUM
Regular
runs online (no lock)
marks dead tuples as reusable
space stays in table file
fast, low overhead
safe to run anytime
VACUUM users;
VACUUM FULL
Full rewrite
exclusive table lock
rewrites entire table compacted
returns space to OS
slow on large tables
blocks reads AND writes
VACUUM FULL users; -- careful!
Rule: Use FULL only when you need to reclaim disk. Expect downtime or use pg_repack instead.

autovacuum.sql 13 / 20
// background worker

Autovacuum does
this automatically.

Runs in background. Triggered when dead tuples exceed a threshold. Default settings work for most DBs — but high-churn tables need tuning.

-- defaults (postgresql.conf)
autovacuum                   = on
autovacuum_vacuum_scale_factor = 0.2   -- 20% dead tuples
autovacuum_vacuum_threshold   = 50    -- + 50 dead rows
autovacuum_analyze_scale_factor= 0.1   -- analyze at 10%

-- per-table override (high-churn tables)
ALTER TABLE events SET (
  autovacuum_vacuum_scale_factor = 0.01,  -- 1% threshold
  autovacuum_vacuum_cost_delay   = 2       -- less throttle
);
autovacuum = on by default
tune per-table for hot tables

wraparound.sql 13 / 20
// the real horror

Transaction ID Wraparound

Every row stores the XID (transaction ID) that created it. XIDs are 32-bit — about 4 billion values.

VACUUM freezes old XIDs
VACUUM FREEZE replaces old XID with a special "frozen" marker — permanently visible to all transactions. Without this, Postgres will shut down your DB to force a vacuum before wraparound occurs.
Monitor: age(datfrozenxid) in pg_database — keep it below 200M

See it yourself.

Check dead tuple counts and last vacuum time for your tables:

-- find tables with most dead tuples
SELECT
  relname,
  n_dead_tup,
  n_live_tup,
  last_vacuum,
  last_autovacuum
FROM   pg_stat_user_tables
ORDER BY n_dead_tup DESC
LIMIT  5;
-- vacuum + update stats on a table
VACUUM ANALYZE users;

-- check xid age (wraparound risk)
SELECT datname, age(datfrozenxid) AS xid_age
FROM   pg_database
ORDER BY xid_age DESC;
n_dead_tup → bloat signal
xid_age > 200M → act now

VACUUM is not optional.

  • MVCC = dead tuples after every UPDATE/DELETE
  • VACUUM marks dead space reusable (no lock)
  • VACUUM FULL rewrites table compacted — exclusive lock
