-- what lives in the page header

The PageHeader
struct

24 bytes at byte 0 of every page. Postgres reads this before anything else.

-- from src/include/storage/bufpage.h
typedef struct PageHeaderData {
  pd_lsn        PageXLogRecPtr  -- last WAL record for this page
  pd_checksum   uint16          -- optional checksum
  pd_flags      uint16          -- PD_HAS_FREE_LINES, etc.
  pd_lower      LocationIndex   -- end of item pointers ↓
  pd_upper      LocationIndex   -- start of free space   ↑
  pd_special    LocationIndex   -- start of special space
  pd_pagesize_version  uint16  -- size + layout version
  pd_prune_xid  TransactionId   -- oldest pruneable XID
}
free space = pd_upper − pd_lower
Two offsets, one gap. Postgres knows instantly if a row fits.
pd_lsn — crash safety
Links page to WAL. Replays from here on crash recovery.

-- real cost of one row from disk

1 row = 1 page read.
Always.

EXPLAIN BUFFERS doesn't lie. Fetch one row — Postgres charges you one page.

EXPLAIN (ANALYZE, BUFFERS) SELECT *
FROM users WHERE id = 42;

------------------------------------------------------------
Index Scan using users_pkey on users
  (cost=0.43..8.45 rows=1)
  (actual rows=1 loops=1)
  Index Cond: (id = 42)
    Buffers: shared read=1     ← one page loaded from disk
Planning Time: 0.2 ms
Execution Time: 0.8 ms
shared read=1 means one 8KB page was fetched from disk. That page likely has tens of other rows Postgres just ignored. But it paid the full page cost anyway.

See CTIDs
yourself.

-- every row has a physical address
SELECT ctid, id, email
FROM users LIMIT 5;

  ctid   | id | email
---------+----+-------------------
 (0,1)  |  1 | alice@example.com
 (0,2)  |  2 | bob@example.com
 (0,3)  |  3 | carol@example.com
 (1,1)  | 43 | dave@example.com   ← new page
 (1,2)  | 44 | eve@example.com
-- confirm the block size
SHOW block_size;

 block_size
-----------
 8192

(0,1) = page 0, slot 1. (1,1) = Postgres moved to a new 8KB page.

-- tl;dr

Quick recap

  • page — the atom. Postgres never reads smaller.
  • 8 KB fixed. Compile-time constant. Always 8192 bytes.
  • layout — header → item pointers → free space → tuples
  • CTID = (page, item) — physical address of every row
  • I/O is page-level — one row fetch still costs one full page
