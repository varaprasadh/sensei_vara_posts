$ # what reflog actually tracks

Every move HEAD made.

Reflog logs every time HEAD moved — commits, checkouts, resets, merges, rebases. Locally. Always.

Lives at .git/logs/HEAD. Not in your remote. Not in git log.

$ # the output, line by line

Read it like a log.

$ git reflog
d4a1cc7 HEAD@{0}: reset: moving to HEAD~5
e89df01 HEAD@{1}: commit: add tests
f12a08d HEAD@{2}: commit: implement search
7e2dc1f HEAD@{3}: merge feature/api
99c4ab2 HEAD@{4}: checkout: moving from main to feature/api
b72cf81 HEAD@{5}: commit: add readme
SHA · HEAD@{N} · what happened

Last move = HEAD@{0}. Go back N steps with HEAD@{N}.

05 / 08
$ # the recovery move

Reset back to
before the mistake.

# I want to undo that --hard reset
$ git reset --hard HEAD@{1}
# back to e89df01 (one move ago)

Or grab the SHA directly: git reset --hard e89df01.

Your "lost" commits aren't lost. They're orphaned. Reflog finds them.

06 / 08
$ # branch deleted? same trick

Recover a deleted branch.

$ git branch -D feature/api
Deleted branch feature/api (was f12a08d).

# minutes later: I needed that
$ git branch feature/api f12a08d
# branch is back, pointing at the same tip

Branches = pointers. Recreating one = writing the SHA back.

Lost the SHA? git reflog remembers — that "was f12a08d" line is also in there.

$ # the small print

What reflog can't save.

It's powerful, not magical. Three things to know.

01
Local only

Reflog is on YOUR machine, not the remote. Force-pushed something? Their reflog won't help you.

02
Expires

git gc prunes unreachable commits after ~90 days (configurable).

03
Uncommitted work

Files you never git add-ed and git commit-ed don't have a reflog entry. Save often.
