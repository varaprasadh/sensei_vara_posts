The big 3.

Out of ~15 hook points, three earn their keep on day one.

01
pre-commit
Runs before the commit is finalized. Lint, format, type-check.
02
commit-msg
Runs against the commit message. Enforce conventional commits.
03
pre-push
Runs before push. Run tests one last time.
+ bonus
post-merge / post-checkout
Refresh deps, regenerate env files after branch swaps.

All client-side. Live in your local .git/hooks/.

$ # a real one, head to toe

Lint before you commit.

Stop bad code at the door. Block the commit if eslint fails.

#!/bin/bash
# .git/hooks/pre-commit

# only lint staged JS files
STAGED=$(git diff --cached --name-only --diff-filter=ACM | grep '\.js$')

if [ -z "$STAGED" ]; then exit 0; fi

echo "→ linting $STAGED"
npx eslint $STAGED
if [ $? -ne 0 ]; then
  echo "✗ lint failed. commit aborted."
  exit 1
fi
exit 0

Don't forget chmod +x .git/hooks/pre-commit.

Share them with the team.

Default .git/hooks/ isn't tracked. Every teammate would set up their own. Use a wrapper.

node
husky
Node-based. Very common in JS / TS projects.
binary
lefthook
Fast, language-agnostic, single binary.
native
core.hooksPath
Git trick: point hooks to a tracked folder.
# option 3: vanilla git, zero deps
$ git config core.hooksPath .githooks
$ git add .githooks/ && git commit -m "share hooks"

Pick one + document the install step in your README.

Server-side: pre-receive.

Client hooks are skippable (--no-verify). Server hooks aren't. They run on the remote when someone pushes.

# on the git server: hooks/pre-receive
while read old new ref; do
  # reject pushes to protected branches by non-admins
  if [ "$ref" = "refs/heads/main" ] && [ "$USER" != "admin" ]; then
    echo "✗ direct pushes to main blocked"
    exit 1
  fi

  # reject commits without a JIRA tag in the message
  git log "$old..$new" --format=%s | grep -qvE '^[A-Z]+-[0-9]+' && exit 1
done
exit 0

GitHub, GitLab, etc. give UI for the same idea (branch protection, required checks).

$ # what hurts teams

Keep them fast + skippable.

Hooks fail teams when they slow down or block emergencies. Four rules:

01
fast
pre-commit > 2s = your team hates you. Optimize or move to CI.
02
skippable
--no-verify for emergency commits should always work.
03
scoped
Lint only staged files, not the whole repo. Use --diff-filter.
04
silent on success
Verbose only on failure. Don't drown the terminal in passes.
