Open the box.

Every git repo has a .git/ folder. Here's what's inside.

$ ls .git/
HEAD            # the current pointer
config          # repo settings
objects/        # commits, trees, blobs
refs/           # branch + tag pointers
hooks/          # scripts fired on events
index           # the staging area
logs/           # reflog lives here
info/           # exclude file, more

7 things you've been ignoring.

$ # the content store

Objects: blobs,
trees, commits.

Every file, every snapshot, every commit. All stored as objects, addressed by SHA.

blob
the raw contents of a single file
tree
a directory listing — filenames → blobs / trees
commit
a tree pointer + parent pointer(s) + message

All sit under .git/objects/<first-2>/<rest-of-sha>.

$ # the pointers

Refs: names
for commits.

Branches and tags are just text files holding one SHA.

$ cat .git/refs/heads/main
d4a1cc7e5a8b2f8c9b1e6d7a3f4b8c9e0d1a2b3c

$ cat .git/refs/tags/v1.0
b72cf81d3e9a8f7c6b5d4e3a2c1f0e9d8c7b6a5d

Yes, that simple. A branch is a sticky note holding a SHA.

HEAD: where
you are now.

A file that points to a branch (or directly to a commit, when detached).

$ cat .git/HEAD
ref: refs/heads/main

# detached HEAD looks like:
d4a1cc7e5a8b2f8c9b1e6d7a3f4b8c9e0d1a2b3c

HEAD is the "you are here" marker on your repo's map.

$ # the staging area, on disk

Index: staged,
on disk.

A binary file listing what git add prepared for the next commit. Not just a concept — it lives here.

$ git ls-files --stage
100644 a3f8e90b... 0  README.md
100644 b72cf81d... 0  package.json
100644 c91e3b42... 0  src/index.js

Each line = mode, blob SHA, stage, path. That's the staging area.

Three more rooms.

The supporting cast that quietly powers your everyday git.

01
hooks/
scripts that fire on commit, push, etc. Deep-dive next post.
02
config
repo-local settings — user email, remote URLs, merge tools.
03
logs/
every HEAD movement, ever. This is what powers git reflog.
04
info/
exclude patterns — a local-only .gitignore that never gets committed.

Small files. Big effect on how your repo behaves.

Quick recap

  • .git/ is the whole repo — your files are just a snapshot
  • objects store content; refs name commits
  • HEAD tracks where you are
  • index is the staging area, on disk
  • hooks, config, logs live right next to them
