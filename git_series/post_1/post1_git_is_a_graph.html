03 / 08
$ # what's inside one commit

A commit is a snapshot
+ a parent.

Not a diff. A full snapshot of your project + a pointer to the previous one.

$ git cat-file -p HEAD
tree    9c2b...      # snapshot of files
parent  d4a1...      # the prev commit
author  "alice" 2026-05-22
committer "alice"
message "add tests for auth flow"

That parent line is the edge in the graph.

Strip everything else and you've got: node + arrow back.

$ # branches, plain and simple

Branches are labels
that move.

A branch isn't a copy. It's a sticky note pointing at one commit.

New commit on main? The label slides forward. No copy. No tree.

$ # when history forks

Two commits.
One parent.

That's a divergence. Two branches built from the same starting commit.

Two paths. Same root. A graph, not a list.

merge.git
06 / 08
$ # when history rejoins

Merge = one commit
with two parents.

That's the only special thing about a merge. Two arrows out the back.

Every other commit has 1 parent. Merges have 2. That's the whole spec.

$ # see the graph yourself

One command.
Real picture.

Drop this into any repo. The ASCII tree is the real story.

*   7e2dc1f (HEAD -> main) Merge feature/api

| * 99c4ab2 (feature/api) add tests for /search

* | d4a1cc7 bump deps
* | c91e3b4 fix null check in auth
|/
*   b72cf81 add readme
*   a3f8e90 init

That's not a diagram. That's your actual repo.
