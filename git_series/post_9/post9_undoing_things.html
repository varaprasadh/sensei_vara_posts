Four ways to undo.

Each one undoes something different. Pick by what you're trying to unmake.

reset
rewind a branch
revert
new commit that undoes another
restore
restore files from a snapshot
checkout
the OG, still works (legacy)

Different scope, different blast radius. Don't mix them up.

git reset
03 / 08
$ # rewind the branch

reset = move the pointer.

Moves your current branch back to an earlier commit. Three modes for how much to also touch.

$ git reset --soft  HEAD~1   # branch back, keep index + working dir
$ git reset --mixed HEAD~1   # branch back, keep working dir (default)
$ git reset --hard  HEAD~1   # branch back, nuke index + working dir

Local-only operation. Don't reset published history.

git revert
04 / 08
$ # the safe undo

revert = new commit, inverse.

Makes a new commit that undoes the changes of an old one. History stays linear, others stay happy.

$ git revert e89df01
[main 3a4b5c6] Revert "add bug feature"

Use this on shared branches. Reset would rewrite history; revert just adds.

git restore
05 / 08
$ # modern file recovery

restore = file-level undo.

The modern replacement for parts of checkout. Restore files from any source (working dir, index, or a commit).

$ git restore app.js               # discard working-dir edits
$ git restore --staged app.js      # un-stage (move index → HEAD)
$ git restore --source=e89df01 app.js   # restore from a specific commit
working dir
your edits
index
the staging area
HEAD / sha
any commit

Files only. Doesn't touch the branch pointer.

git checkout
06 / 08
$ # the legacy multi-tool

checkout still works.

Older, broader. Today, prefer switch for branches and restore for files. But many guides + scripts still use it.

$ git checkout main         # switch to branch (use `git switch` instead)
$ git checkout app.js       # restore file from HEAD (use `git restore`)
$ git checkout e89df01      # detached HEAD — look at an old commit

Still around for compatibility. New code: prefer switch + restore.

$ # which one when

Pick by what you want to undo.

Read left to right. Each row: question, then the command.

  • undo a shared commit? → git revert <sha>
  • undo local commits only? → git reset --soft|--mixed|--hard
  • undo edits in a file? → git restore <file>
  • un-stage a file? → git restore --staged <file>
  • look at an old commit? → git switch --detach <sha>
