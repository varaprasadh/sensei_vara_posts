Binaries bloat history.

Add a 50 MB asset, change it 20 times, your .git/ is now 1 GB+ — forever. Cloning the repo means downloading all old versions.

Affects: game assets, design files (Sketch/Figma exports), ML model weights, PDFs, video, mp3.

$ # the trick

Replace files with
pointers.

LFS swaps the large file in git with a tiny text pointer. The real content lives on a separate storage server.

Repo stays small. Files still work.

$ # what's actually in the repo

A pointer is 3 lines.

That's it. The whole file as git sees it.

$ cat assets/model.bin
version https://git-lfs.github.com/spec/v1
oid sha256:a7f3e91b8d4c2f1e6a9b8c7d5e4f3a2b1c0d9e8f...
size    52428800   # 50 MB

That's all that's in git. The actual 50 MB binary lives on the LFS server, fetched on checkout.

05 / 08
$ # 5-minute install

3 commands to turn it on.

# one-time, per user/machine
$ git lfs install

# in the repo: track patterns
$ git lfs track "*.psd" "*.bin" "*.mp4"
# adds a .gitattributes entry

$ git add .gitattributes
$ git add assets/model.bin
$ git commit -m "track big files via LFS"
$ git push
# pointer goes to git, file goes to LFS server

After this, every matching file flows through LFS.

$ # the clone behavior

Pull pointers first,
files on demand.

By default, clone fetches pointer files + LFS objects for the current checkout. Old versions stay on the server.

# default: get pointers + current files
$ git clone https://github.com/team/repo

# pointers only (skip file downloads, fast)
$ GIT_LFS_SKIP_SMUDGE=1 git clone https://github.com/team/repo

# fetch a specific old version's LFS objects later
$ git lfs pull --include="assets/model.bin"

Big repos clone fast. Small files come on demand.

$ # don't use it for...

Not a silver bullet.

LFS has costs. Skip it when these apply.

01
small files
< 1 MB? Regular git is fine. LFS adds friction and another server in the loop.
02
frequently edited
Every edit = new LFS object. Bandwidth + storage costs balloon fast.
03
public OSS repos
LFS storage costs $$$. Every fork eats into your quota — surprise bills.
04
alternatives
S3/CDN + scripts, sparse checkout, partial clone, submodules.

If git wasn't going to bloat anyway, you probably don't need LFS.
