When you must rewrite.

Three situations where you cannot just "make a new commit" — you have to go back and edit the past.

01
secrets
API key, password, or .env committed by accident. Now in history forever.
02
big files
Binary that should've used LFS. Now bloating .git/ for everyone, forever.
03
mistakes
Wrong author email, sensitive data in commit message, accidental merge of the wrong branch.

All 3 require touching past commits — which means new SHAs for every commit after.

$ # the modern tool

git filter-repo
= the modern way.

Built by git maintainers as the replacement for the deprecated filter-branch. Fast. Safe-ish. Requires pip install git-filter-repo.

# remove a secrets file from all history
$ git filter-repo --path .env --invert-paths

# remove all .psd files from history
$ git filter-repo --path-glob '*.psd' --invert-paths

# replace a string everywhere
$ git filter-repo --replace-text <(echo "API_KEY_123==>REMOVED")

Works on a fresh clone (it refuses to touch your dev repo by default — safe).

$ # the friendly tool

BFG = simpler,
slightly different.

Java tool. 10–100x faster than filter-branch, smaller feature set, much easier syntax.

# remove all files over 50 MB from history
$ bfg --strip-blobs-bigger-than 50M

# remove .env from all commits
$ bfg --delete-files .env

# replace secrets in text files
$ bfg --replace-text secrets.txt

Pick filter-repo for power, BFG for one-liners. Both work.

$ # the mandatory cleanup

Force-push
+ warn everyone.

Every commit after the rewrite point has a new SHA. The remote's history must be replaced. Collaborators must re-clone.

$ git push --force-with-lease origin --all
$ git push --force-with-lease origin --tags
$ git gc --aggressive --prune=now   # reclaim local space

# tell teammates: re-clone, don't pull.

Open PRs against the rewritten branch will break. Plan ahead.

What rewriting can't save.

Rewriting the local graph is the easy part. Cleaning up the fallout is the hard part.

01
once pushed, secrets stay
GitHub/GitLab keep them in events, forks, and caches. Rotate the secret.
02
PRs & CI break
Open PRs, build artifacts, and CI pipelines all reference old SHAs. They die.
03
public forks
You can't rewrite theirs. Once it's out there, it's out there. Bad news travels.
04
always backup first
Clone the repo somewhere safe before rewriting. Disasters are reversible only if you have a copy.
