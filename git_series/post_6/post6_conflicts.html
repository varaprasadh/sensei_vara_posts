$ # the cause

Two branches.
Same lines.

Git can auto-merge most edits. But when both branches changed the exact same lines, it can't pick — so it asks you to.

your branch
function greet() {
  return 'hi'
}
their branch
function greet() {
  return 'hello'
}

Both edited the same return. Git's stuck.

Reading the markers.

function greet() {
<<<<<<< HEAD
  return 'hi'
=======
  return 'hello'
>>>>>>> feature/greeting
}
  • <<<<<<< HEAD — start of YOUR version (current branch)
  • ======= — the divider
  • >>>>>>> feature/greeting — end of THEIR version (incoming)

Top = yours. Bottom = theirs.

$ # the 4-step fix

Find. Decide. Fix.
Mark resolved.

Same four steps every single time. Memorize this.

  • 1. Find — git status lists conflicted files (both modified)
  • 2. Decide — pick yours, theirs, or both (combined)
  • 3. Fix — edit the file, remove the markers
  • 4. Mark resolved — git add <file> ("I handled it")

Then git merge --continue (or --rebase --continue) finishes the job.

$ # the one command to keep open

git status
= your map.

Lost mid-merge? Run it. It literally tells you the next command.

$ git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")

Unmerged paths:
  (use "git add <file>..." to mark resolution)
        both modified:   greet.js
        both modified:   utils.js

Untracked files:
  ...

Tells you exactly what to do next. Re-run it constantly.

07 / 08
$ # escape hatch

Bail out, clean.

If it's overwhelming, you can always undo. Git keeps the pre-merge state on standby.

$ git merge --abort         # back to before the merge
$ git rebase --abort        # back to before the rebase
$ git cherry-pick --abort   # back to before the cherry-pick

No shame in retreating. Try again with fewer changes.
