$ # what a branch actually is

A branch is one file.

Holding one commit SHA. That's the entire branch.

$ cat .git/refs/heads/main
d4a1cc7e5a8b2f8c9b1e6d7a3f4b8c9e0d1a2b3c

40 hex characters. That's your branch.

refs/heads/main = 1 SHA = 40 bytes

$ # try this in any repo

Proof, in 3 commands.

Open any git repo. Run these. Watch the abstraction collapse.

f12a08d3e9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4

$ git rev-parse feature/api
f12a08d3e9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4

Three branches. Three text files. That's the whole branch system.

$ # one more layer

HEAD points at a branch.

Your current branch is whatever HEAD is pointing at. So HEAD is a pointer to a pointer.

HEAD → branch → commit. Two arrows. That's it.

$ # what `git switch` actually does

Switching = move HEAD.

It rewrites one file. That's the whole switch.

$ git switch feature/api

# .git/HEAD is now:
ref: refs/heads/feature/api

# working dir is updated to match
# feature/api's snapshot

Plus updating your files to match — but that's just a checkout side-effect.

07 / 08
$ # create / delete are equally cheap

Create. Delete. No copies.

Branch ops touch one tiny file. No history is duplicated. No code is moved.

// create
$ git branch feature/x
writes a new 40-byte text file at .git/refs/heads/feature/x with the current commit SHA.
// delete
$ git branch -d feature/x
deletes that text file. Commits stay. Code stays. Just the label is gone.

This is why branches in git are basically free.
