How commits go
missing.

Three ways. All survivable.

01
reset --hard branch moves back — commits orphaned
02
deleted branch branch ref gone — commits dangling
03
force-push remote refs rewritten — old commits dangling on remote

All 3 leave the actual commits intact — just nothing pointing at them.

Find the lost
SHA.

Reflog tracks every HEAD move. Even the destructive ones.

$ git reflog
d4a1cc7 HEAD@{0}: reset: moving to HEAD~5
e89df01 HEAD@{1}: commit: add tests          ← we want this
f12a08d HEAD@{2}: commit: implement search
b72cf81 HEAD@{3}: commit: add readme
a3f8e90 HEAD@{4}: commit (initial): init
...

Grab the SHA. That's what git reflog is for. (See post 7 for the deep dive.)

$ # when reflog can't help

fsck finds the rest.

When the reflog doesn't list it (e.g. you orphaned in a script), fsck scans for dangling objects.

$ git fsck --lost-found
dangling commit a7f3e91b8d4c2f1e6a9b8c7d5e4f3a2b1c0d9e8f
dangling commit b2c3d4e5f6789abc0123def456789abc01234567
dangling blob   c3d4e5f6789abc0123def456789abc012345678

Then inspect with git show <sha> to find the right one.

$ # the rescue move

Re-attach the SHA.

Got the SHA. Three ways to bring it back.

# option A — make a branch at the lost commit
$ git branch recovered a7f3e91

# option B — cherry-pick the lost commit onto current branch
$ git cherry-pick a7f3e91

# option C — reset HEAD back to it (if it's the right tip)
$ git reset --hard a7f3e91

Pick by what makes sense. Re-naming with a branch is safest.

Force-push survival.

Your local copy is the truth. The remote's reflog (if you control the server) is the backup.

# you still have the commits locally:
$ git reflog       # find the pre-force-push SHA
$ git reset --hard <pre-force-push-sha>
$ git push --force-with-lease

# you DON'T have them locally?
# GitHub Events API or server-side reflog
# can sometimes save you.

GitHub also keeps a 90-day events log per repo.

Stop losing things.

Four habits. Skip the panic.

01
commit often small commits = small losses
02
prefer revert over reset --hard on shared work
03
--force-with-lease instead of --force
04
dry-run destructive cmds run git status before any further work

Recovery is real. Prevention is cheaper.

Quick recap

  • commits don't get deleted — just unreachable
  • reflog first; git fsck --lost-found second
  • recover with a branch, cherry-pick, or reset to the SHA
  • force-push survival = your local copy + server-side log
  • prevent: small commits, revert > reset, lease > force
