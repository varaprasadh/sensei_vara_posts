// the catch

Lost in the middle.

Models pay more attention to the beginning and end of context. Information buried in the middle gets missed more often.

// "needle in a haystack" test
// hide a fact at different positions in long context

Position in context:     Recall accuracy:
┃ Start (0-10%)           ~99% recall
┃ Early (10-30%)         ~95% recall
┃ Middle (30-70%)         ~87% recall
┃ Late (70-90%)          ~94% recall
┃ End (90-100%)           ~99% recall

// the "U-shaped" attention curve
// models remember beginnings and ends best
// middle = danger zone for critical info

Fix: put important context at the start or end of your prompt, not buried in the middle.

// strategies

Stuff everything vs smart retrieval.

Two opposing philosophies. Both have their place.

// stuff everything
brute force 
// dump all context in
prompt = systemPrompt
  + allDocs        // 200K
  + userQuery

// pros:
✓ simple — no retrieval pipeline
✓ no missed context
✓ great for exploration

// cons:
✗ expensive at scale
✗ slow (high latency)
✗ "lost in middle" risk
// smart retrieval (RAG)
surgical 
// retrieve only what's relevant
chunks = search(query, k=5)
prompt = systemPrompt
  + chunks          // 4K
  + userQuery

// pros:
✓ cheap (small context)
✓ fast (low latency)
✓ scales to any corpus size

// cons:
✗ retrieval can miss context
✗ chunking loses structure
✗ complex pipeline

// long context wins when

When to skip RAG.

Long context isn't always overkill. Sometimes it's the simpler, better solution.

// long context wins
  • Small-to-medium corpus <500 pages. Fits in context. Why build a pipeline?
  • Questions needing full picture "Summarize this entire contract" — can't retrieve a summary.
  • Cross-document reasoning "Compare these 5 reports" — retrieval loses structure.
  • One-off analysis Not worth building RAG infra for a single task.
// RAG wins
  • Massive corpus (millions of docs) Won't fit in any context window. Must retrieve.
  • High-volume production 100K req/day × 200K tokens = bankruptcy.
  • Factoid lookups "What's the return policy?" — 5 relevant sentences beat 500 pages.
  • Frequently updated data Embeddings can be updated incrementally. Re-stuffing = wasteful.

// making it work

Long-context tips.

Practical patterns for getting the most out of large context windows.

// tip 1: put instructions at START and END
prompt = [
  "You are analyzing a codebase...",  // start
  ...allFiles,                        // middle
  "Now answer: " + question,          // end
]

// tip 2: use prompt caching
// cache the 200K doc prefix, pay once
cache_control: { type: "ephemeral" }
// subsequent queries: only pay for new tokens

// tip 3: add structure to long context
// XML tags, headers, file paths → helps model navigate
"<file path='src/auth.js'>...code...</file>"

// tip 4: ask model to cite sources
"Quote the exact passage that supports your answer"
// → forces model to actually find the info

// tl;dr

Context is power.

  • 1M tokens — fit entire codebases, books, log files in one prompt
  • Lost in the middle — models attend less to middle of context. Put key info at edges
  • Cost scales linearly — 200K context = 50x cost of 4K. Use prompt caching
  • Long context vs RAG — small corpus + exploration = stuff it. Large corpus + production = RAG
  • Structure matters — XML tags, clear headers, source citations improve accuracy
