// four reasons to go local

Why local matters.

Four properties no API can offer. All four follow from one fact: the model runs on your machine.

Privacy
Data never leaves your machine. No logs, no training, no ToS anxiety. Medical records, legal docs, private code — all fine.
Cost
Free after hardware. 10k requests/day → $0. API at that volume → $50–500/month depending on model.
Latency
No network round-trip. No cold starts. First token in <100ms on Apple Silicon. Feels instant.
Offline
Works on a plane, in a basement, behind a firewall. No internet dependency in your critical path.

stack.js
03 / 08
// the four pieces

The local stack.

Four tools. Each has one job. Together they replace the API.

runtime
Ollama
One-command server. Downloads models, exposes OpenAI-compatible API on localhost. ollama run llama3 and done.
engine
llama.cpp
C++ inference engine under the hood. Runs quantized models fast on CPU + GPU. What Ollama uses internally.
format
GGUF
Model file format. Single .gguf file = whole model + metadata. Quantization level baked in. Portable.
downloads
HuggingFace
Where the GGUF files live. Thousands of models. Filter by "GGUF" tag. Pull directly into Ollama or llama.cpp.

// hardware sizing guide

Hardware reality.

Unified memory on M-series Macs is unusually good here. GPU VRAM bottlenecks on Windows/Linux.

model size min RAM M-series notes
3B 8 GB ~60 tok/s M1/M2 Air — comfortable
7B 8 GB ~35 tok/s M1 Pro+ — sweet spot
13B 16 GB ~18 tok/s M2 Pro+ — usable
30B 32 GB ~8 tok/s M2 Max — slow but works
70B 48 GB ~3 tok/s M2 Ultra / M3 Max only

7B at Q4 fits in 8 GB. That's a MacBook Air. Not a server rack.

quant.js

// size vs quality trade-off

Quantization: pick your level.

Lower bits = smaller RAM footprint, slightly lower quality. Q4_K_M is the default pick.

Q2_K ~2.5 GB (7B) · 80% quality · too lossy for most
Q4_K_M ~4.1 GB (7B) · ~95% quality · recommended default
Q5_K_M ~5.0 GB (7B) · ~97% quality · good middle ground
Q8_0 ~7.2 GB (7B) · ~99% quality · near-perfect
F16 (fp16) ~14 GB (7B) · 100% · baseline, needs big RAM

Bars = RAM use relative to fp16. Quality drops are barely noticeable at Q4_K_M.

// where local excels

When local wins.

Local models punch above their weight on narrow, repeatable tasks. No API bill accumulating in the background.

local
Code completion
Low latency matters here. 50ms local < 400ms API. Codestral / DeepSeek-Coder-v2 are competitive.
local
Embedding generation
nomic-embed, mxbai — free forever. High volume, zero API cost. Perfect for RAG pipelines.
local
Simple classification
Sentiment, intent, routing. 3B model handles these. Overkill to pay frontier prices.
local
Drafts that get edited
If a human rewrites it anyway, 7B quality is enough. First draft at $0 beats polished draft at $0.05.

api_wins.js

// where API still dominates

When API wins.

Local models can't close every gap. Frontier models earn their bill in these four cases.

API
Agentic tool calling
Reliable multi-step tool use still favors frontier models. Local 7B hallucinates tool schemas under pressure.
API
Long context (128k+)
Running 100k tokens locally needs huge RAM. APIs handle it cheaply. Not worth the hardware cost.
API
Frontier reasoning
Complex analysis, nuanced judgment, creative quality. 7B cannot match GPT-4o or Claude Sonnet here.
API
Low-volume sporadic use
If you're calling 10x/day, the API costs pennies. Don't invest in hardware setup for that volume.

// the default + override rules

The decision rule.

Default to API. Override when a specific condition triggers.

DEFAULT
Start with API-first. Fastest path to production. No hardware, no setup, no ops.
SWITCH when
latency matters — code completion, real-time features, sub-100ms required
SWITCH when
data is sensitive — PII, health records, private IP that can't leave your network
SWITCH when
cost > hardware — API bill exceeds ~$100/mo, hardware pays back in <6 months
The best model is the one that ships. Start simple, go local when the math says so.
