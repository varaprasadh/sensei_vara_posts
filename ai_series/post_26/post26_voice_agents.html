03 / 08
// the human constraint

~700ms before it feels broken.

Human conversation tolerates about a 700ms turn gap. Anything longer feels like a freeze — or a bad phone call.

OK zone (≤ 700ms)
700ms ← threshold
feels frozen →
// what research shows
  <150ms  → feels instant  (same-room conversation)
  150–300ms → feels fast    (good phone call)
  300–700ms → feels okay    (tolerable, acceptable)
  >700ms   → feels broken  (user thinks it crashed)

Your entire pipeline — VAD + STT + LLM + TTS — must fit inside that window.

streaming.js
05 / 08
// the fix: stream everything

Stream all three. Cut perceived latency.

Don't wait for each stage to finish. Pipe partial results forward the instant they arrive.

STT
Streams partial transcripts as you speak — don't wait for silence.
word-by-word → LLM starts thinking before you stop talking
LLM
Streams tokens as they generate — pipe first sentence to TTS immediately.
TTFT matters more than throughput in voice
TTS
Streams audio chunks — speaker plays while rest still generating.
first audio frame can arrive in ~50ms from first token

The pipeline becomes a stream.pipe(stream).pipe(stream) — not three sequential waits.

vad.js
06 / 08
// the hard problem

VAD: knowing when
you stopped talking.

Voice Activity Detection decides when the user's turn ends. Getting it wrong in either direction ruins the experience.

// too eager
low end-of-speech delay 
// triggers early
user: "I want to—"
VAD: speech ended!
→ interrupts mid-sentence
user: // frustrated
Cuts the user off. Feels rude. Trust erodes fast.
// too patient
high end-of-speech delay 
// waits too long
user: "Done."
// ... 1200ms silence ...
VAD: okay, maybe done?
→ awkward dead air
Pregnant pause after every sentence. Feels glitchy.

Best VADs use prosody + energy + neural models. Still an unsolved product problem, not just a signal-processing one.

interrupt.js
07 / 08
// hardest part of the whole system

Interruption
handling.

User starts talking mid-response. You must stop everything, immediately.

// what has to happen in <100ms
if (VAD.detected_speech_while_agent_talking) {
  tts.stop();          // kill audio immediately
  llm_stream.abort(); // cancel generation mid-token
  player.flush();     // drain audio buffer
  context.push({ role: 'partial_assistant', ... }); // save what was said
  // now listen to user
}

The hard parts: audio buffer drain (speakers have 200–400ms of buffered audio), partial context management (what did the agent actually say?), and race conditions when both sides detect speech at once.

08 / 08
// the new frontier

Skip the pipeline.
E2E speech models.

  • OpenAI Realtime API — audio in, audio out, no separate STT/TTS
  • Gemini Live — multimodal, same concept, lower latency
  • faster — eliminates two full round-trips
  • less control — can't swap voices, no transcript guarantee
  • tradeoff — speed vs. customisation. classic pipeline still wins for most prod use cases
Latency is the UX. Every ms you shave
makes the agent feel more human.
