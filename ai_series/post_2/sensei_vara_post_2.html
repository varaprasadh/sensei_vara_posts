03 / 08
// the missing piece

The system prompt.

A hidden instruction the model reads before every user message.

messages: [
  { role: "system", content: "You are a..." }
  { role: "user",   content: "I'm so frustrated!" }
]

Think of it as the model's job description.

It tells the model who it is, what to do, and how to behave — every single turn.

06 / 08
// what goes inside a good one

4 ingredients.

Every solid system prompt has these. In this order.

01 — role
Who are you?
"You are a senior SQL reviewer for an analytics team."
02 — rules
What must / mustn't you do?
"Never run DROP statements. Always explain the WHERE clause."
03 — tools
When to use each tool
"Use run_query for SELECTs. Use explain_plan for slow queries."
04 — format
How to reply
"Reply in markdown. Code in ```sql blocks. Keep it under 200 words."

What it looks like
in production.

role You are a senior code reviewer for pull requests.
role You review JavaScript and TypeScript code for a small team.
rules Flag bugs and security issues first. Style nits last.
rules Suggest, never demand. Explain the "why" behind every comment.
rules If the diff is fine, say so. Don't invent problems.
tools Use get_file_content to read context around the diff.
tools Use run_tests before approving anything that touches /core.
format Reply in markdown. Group comments by severity.
format End with a one-line verdict: APPROVE / REQUEST_CHANGES.

Specific. Boring. Effective.
