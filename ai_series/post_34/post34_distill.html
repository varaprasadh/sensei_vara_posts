Teacher-student learning.

03 / 08
// what transfers

Reasoning patterns, not knowledge.

The student doesn't memorize the teacher's facts. It learns how to think about a specific task domain.

// what distills well
  • Output format & structure JSON schemas, response patterns, consistent formatting
  • Task-specific reasoning "Given X, the answer is Y because Z" patterns
  • Classification decisions Sentiment, intent detection, category mapping
  • Tone & style Professional, concise, domain-appropriate language
// what doesn't transfer
  • World knowledge Small model can't memorize what big model knows
  • Complex multi-step reasoning 5-step chains collapse in small models
  • Rare edge cases Need thousands of examples per pattern
  • General intelligence You get a specialist, not a generalist

Key: distillation creates specialists, not smaller versions of the teacher

// practical pipeline

How to distill in practice.

A step-by-step pipeline from raw data to deployed student model.

step 1
Collect unlabeled inputs
Gather real production inputs. 5K-50K examples depending on task complexity. Cover edge cases.
↓
step 2
Generate teacher labels
Run inputs through the big model (Claude Opus, GPT-4). Save input-output pairs. Quality-filter bad outputs.
↓
step 3
Fine-tune student model
Train a small model (Llama 8B, Mistral 7B) on the teacher's outputs. 2-5 epochs, low learning rate.
↓
step 4
Evaluate & deploy
Compare student vs teacher on held-out test set. If within 5-10% quality, deploy. Monitor for drift.

// when to use what

Distill vs fine-tune vs prompt.

Three different techniques for making models better at your task. Choose based on volume and quality needs.

// prompting
zero setup 
// best when:
- < 100 requests/day
- task changes frequently
- no training data yet
- need it working today

// cost: high per-request
// quality: good (big model)
// setup: minutes
Start here. Move to distillation when volume grows and the task stabilizes.
// distillation
best of both 
// best when:
- > 10K requests/day
- task is well-defined
- big model works well
- need to cut costs 10x

// cost: low per-request
// quality: 90% of teacher
// setup: days
Sweet spot for production. Teacher does R&D, student does serving.

// implementation

Distillation in code.

A minimal pipeline: generate labels, format for training, fine-tune.

// 1. generate teacher labels
const dataset = [];
for (const input of rawInputs) {
  const output = await opus.chat({
    system: "Classify this support ticket.",
    user: input
  });
  dataset.push({ input, output: output.text });
}

// 2. format as JSONL for fine-tuning
dataset.forEach(d =>
  appendLine("train.jsonl", {
    messages: [
      { role: "user", content: d.input },
      { role: "assistant", content: d.output }
    ]
  })
);

// 3. fine-tune student
const job = await openai.fineTuning.create({
  model: "gpt-4o-mini", training_file: "train.jsonl"
});

// recap

Distillation cheatsheet.

  • Distillation = big model generates labels, small model learns to reproduce them
  • What transfers = reasoning patterns, output format, style. Not raw world knowledge.
  • Pipeline = collect inputs, label with teacher, fine-tune student, evaluate, deploy
  • When to use = high volume, stable task, big model already works well. Not for prototyping.
  • Cost savings = 10-75x cheaper inference with 90-97% quality retention
