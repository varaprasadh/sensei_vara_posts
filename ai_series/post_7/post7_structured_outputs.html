// the problem

Apps need shapes.

A model returns prose. Your app needs a row in a table.

// what the model returns
prose
"Sure! It looks like Maya Chen at maya@acme.io has a high-priority issue with her billing dashboard not loading after the latest update."
// what your app needs
shape 
const ticket = {
  name: "Maya Chen",
  email: "maya@acme.io",
  priority: "high"
}

Parsing the prose is brittle. There's a better way.

schema.js
04 / 08
// the proper way

JSON mode.

Tell the API what shape you want. The provider enforces it.

const res = await openai.chat.completions.create({
  model: "gpt-4o",
  messages: [
    { role: "user", content: ticketText }
  ],
  response_format: {
    type: "json_schema",
    json_schema: {
      name: "ticket",
      schema: ticketSchema   // ← your shape
    }
  }
});

const ticket = JSON.parse(res.choices[0].message.content);
// guaranteed to match ticketSchema. no try/catch.

Same idea in Anthropic (tool use) and Gemini (responseSchema).

contract.js
05 / 08
// schema is the contract

Define the shape once.

type // what each field is
"priority": { "type": "string" }
required // fields the model must return
"required": ["name", "email", "priority"]
enum // only these values are allowed
"enum": ["low", "med", "high"]
description // hints the model uses to fill it
"description": "Customer email if mentioned, else null"
schema → model → typed JSON

Support ticket → row.

// inbox.txt
free-form
"Hey, this is Jordan from Acme (cust ID C-8821). Our billing page has been throwing a 500 since yesterday's release — pretty urgent, we can't invoice clients. Help?"
// db.tickets.insert
structured 
{
  severity: "high",
  category: "billing",
  customer_id: "C-8821",
  summary: "Billing page 500 since release"
}

Now it goes straight into your DB. No regex. No "did the model add a preamble?"
