// input filter 1

PII detection: before the model.

Don't send private data to a third-party API if you can help it. Block or redact first.

function sanitizeInput(text) {
  // regex patterns catch the obvious ones
  text = text.replace(/\b\d{3}-\d{2}-\d{4}\b/g, "[SSN]");     // SSN
  text = text.replace(/\b\d{16}\b/g,           "[CARD]");    // card
  text = text.replace(/[\w.]+@[\w.]+\.\w+/g,   "[EMAIL]");   // email
  // NER model catches names, addresses, etc.
  return nerRedact(text);
}
regex
Structured PII
SSNs, card numbers, phone, email. High precision, cheap.
NER model
Unstructured PII
Names, addresses, org names. Needs an NLP model (spaCy, Presidio).

injection.js
04 / 08
// input filter 2

Prompt injection: three defenses.

Attackers embed instructions in user content. None of these are foolproof — layer all three.

  • heuristics
    Block suspicious phrases: "ignore previous instructions", "disregard above", "new persona", "DAN mode"
    Cheap. Noisy. First line only — easy to bypass with paraphrasing.
  • classifier
    Fine-tuned binary model: "is this input trying to override the system prompt?"
    ~100ms latency hit. Worth it for high-risk routes. Rebust ML-Guard, Llama Guard.
  • structure
    Structural separation: wrap user input in XML tags, never inline with instructions
    <user_input>{content}</user_input> — model less likely to treat it as a command.
No single defense stops all injection. Defense-in-depth is the only answer.

schema.js

// output filter 1

Schema validation: reject & retry.

LLMs hallucinate structure. JSON mode helps but doesn't guarantee correct shape. Validate every time.

import { z } from "zod";

const ReplySchema = z.object({
  answer: z.string().min(1),
  confidence: z.number().min(0).max(1),
  sources: z.array(z.string()).min(1),
});

const parsed = ReplySchema.safeParse(JSON.parse(raw));
if (!parsed.success) {
  // feed error back, retry once
  return callLLM({ ...messages, error: parsed.error.format() });
}
Error-feedback retry is surprisingly effective — the model self-corrects ~80% of the time.

content_checks.js
06 / 08
// output filter 2

Content checks: three passes.

Schema is correct shape — doesn't mean the content is safe. Run these after every model response.

  • PII leak
    Did the model echo back redacted tokens or hallucinate real PII from context?
    Re-run the same input sanitizer on the output. Block if match. Log for audit.
  • toxic
    Classifier or moderation API (OpenAI moderation, Perspective API) for harmful/hateful content.
    Tune threshold per use-case — medical apps need stricter floors than dev tools.
  • citations
    For RAG: require every factual claim to cite a retrieved chunk. Reject bare assertions.
    Dramatically reduces hallucination surface. Adds traceability for audits.
Output checks add ~50–200ms per call. Almost always worth it in production.

Rate limits: one bad actor = $$$$.

Safety issues scale with usage. Guardrails without rate limits are incomplete — an attacker can just spam.

// failure modes

Guardrails fail in two directions.

// too strict
false positives 
- "ignore that bug" → blocked
- doctor@hospital.com → blocked
- SSN in a help article → blocked
- adversarial red-team → passes
Frustrated users. Support tickets. Churn. Prod rules loosened under pressure.
// too loose
false negatives 
- jailbreak via Unicode
- injection via RAG chunks
- PII slips through NER gap
- schema valid, content toxic
False sense of security. Real leaks. Incident reports. Compliance failures.
Test with adversarial prompts before launch — garak, promptbench, and manual red-teaming sessions.
Guardrails are never done. Tune thresholds in prod, monitor failure rates, iterate.
