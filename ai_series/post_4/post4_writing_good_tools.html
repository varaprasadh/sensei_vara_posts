// quick refresher

A tool is a function.

You declare it. The model asks to call it. You run it. You hand the result back.

model → asks for → tool → result

The model picks tools by reading their names and descriptions.

Bad name. Vague description. Model skips your tool — or invents the wrong one.

The bad tool.

Vague name. No description. Untyped blob param. Pure guesswork for the model.

  name: "process",
  description: "",
  parameters: { data: "any" }

// what to do instead

The good tool.

Clear name. Sentence-long description. Typed, named params.

{
  name: "get_weather",
  description: "Get the current weather for a city.
                Call this when the user asks about
                temperature, rain, or forecast.",
  parameters: {
    city: { type: "string", required: true },
    unit: { type: "enum", values: ["C", "F"] }
  }
}
model output
get_weather({ city: "Tokyo", unit: "C" })

05 / 08
// the 4 levers

4 things to nail.

Every solid tool def has these. Skip one, the model fumbles.

01 — name
verb_noun, snake_case
"get_weather", "search_inventory". Tells the model what it does at a glance.
02 — description
What + when to call it
"Get current weather. Call when user asks about temp, rain, or forecast." Be specific.
03 — parameters
Typed, named, documented
Use types, mark required, list enums. No "data: any". One param per concept.
04 — return shape
Predictable JSON
Same shape every call. Errors as { error: "..." }, not exceptions.

// names matter most

The model picks by name first.

If the name is wrong, it never even reads the description.

// vague
skipped 
do_thing(input)
handle(x)
run(cmd)
fetch_stuff(q)
Model can't tell what each does. Picks none of them.
// specific
picked 
search_inventory(query, limit)
send_email(to, subject, body)
get_user_orders(user_id)
cancel_subscription(id)
Verb_noun + meaningful args. Model picks confidently.

Name = the model's first read. Make it count.

// a real one, annotated

What it looks like
in production.

name search_inventory
desc Search the product catalog. Call this when the user asks if something is in stock, by name or SKU.
param query: string (required) — product name or SKU
param limit: number (optional, default 10) — max results
param in_stock_only: boolean (optional, default false)
return { results: [{ sku, name, price, stock }], total: number }
return on error: { error: "string explaining what went wrong" }

Boring. Typed. Predictable. That's the goal.
