// the vibes problem

Why "looks right" fails.

LLM output is non-deterministic. Same prompt, different day, different model version = different output. You need automated checks.

// traditional software
deterministic 
add(2, 3) // always 5
add(2, 3) // always 5
add(2, 3) // always 5

// assert(result === 5)
Same input = same output. Every time. Easy to test with exact assertions.
// LLM software
non-deterministic 
summarize(doc) // "The paper shows..."
summarize(doc) // "This study finds..."
summarize(doc) // "Researchers found..."

// assert(result === ???)
Same input, different output every time. You can't test with === anymore.

// level 1: unit tests

Golden examples.

Curate input/output pairs that represent correct behavior. Test against properties, not exact strings.

// golden example test
const golden = {
  input: "Summarize: The cat sat on the mat...",
  expected: {
    contains: ["cat", "mat"],           // key facts present
    maxLength: 100,                     // not too long
    sentiment: "neutral",              // right tone
    noHallucination: ["dog", "bird"]  // not in source
  }
}

const result = await summarize(golden.input)
assert(result.length <= golden.expected.maxLength)
assert(golden.expected.contains.every(
  w => result.includes(w)
))

Test properties, not exact strings. Contains, length, format, absence of hallucination.

// level 2: eval suites

Measure with metrics.

Run your prompt against 50-200 test cases. Score each output. Track aggregate metrics over time.

01 — accuracy
Correctness
Does the output contain the right answer? Compare against human-labeled ground truth.
02 — relevance
Relevance
Is the response on-topic? Use an LLM-as-judge or cosine similarity to reference answers.
03 — safety
Safety
Does it refuse harmful prompts? Does it leak PII? Run adversarial inputs through every deploy.
04 — format
Format compliance
Valid JSON? Correct schema? Right language? Structural checks that can be automated.

Target: accuracy > 92%, safety = 100%, format = 100%

// level 3: regression

New model, broken app.

GPT-4o to GPT-4.1. Claude 3.5 to Claude 4. Every model update can break your carefully tuned prompts.

// regression test: compare model versions
const baseline = loadResults("eval_gpt4o_v1.json")
const current  = await runEval("gpt-4.1", testCases)

for (const tc of testCases) {
  const oldScore = baseline[tc.id].score
  const newScore = current[tc.id].score

  if (newScore < oldScore - 0.05)  // 5% tolerance
    fail(`Regression: ${tc.id}`)
}

// aggregate check
const avgDelta = mean(deltas)
assert(avgDelta >= -0.02, "Overall quality dropped")

Run evals on every model upgrade. Catch regressions before users do.

// level 4: A/B testing

Test prompts in production.

Two prompts. Split traffic. Measure which one performs better on real user queries.

// A/B test two prompt variants
async function handleQuery(query, userId) {
  const variant = getVariant(userId) // "A" or "B"

  const prompt = variant === "A"
    ? "You are a helpful assistant..."     // control
    : "You are a concise expert..."         // challenger

  const result = await llm(prompt, query)

  // log for analysis
  logMetric({
    variant, userId,
    latency: result.ms,
    thumbsUp: null,  // user fills later
    tokens: result.usage.total
  })
}

Measure: thumbs-up rate, latency, token cost, task completion.

// the full loop

Eval-driven development.

Evals aren't a one-time thing. They're a CI pipeline that runs on every prompt change.

step 1
Change prompt or model
Edit system prompt, switch model version, tweak temperature, add few-shot examples.
↓
step 2
Run eval suite
100+ test cases. Score accuracy, safety, format, latency. Takes 2-5 minutes in CI.
↓
step 3
Compare to baseline
Regression check. If accuracy drops > 2% or safety fails > 0, block the merge.
↓
step 4
Ship or iterate
Green? Deploy. Red? Fix the prompt. Add failing case to your golden set. Repeat.

// recap

Test like you mean it.

  • LLM output is non-deterministic — test properties, not exact strings
  • Build golden examples — curated input/output pairs with property assertions
  • Run eval suites with accuracy, relevance, safety, and format metrics
  • Regression test every model upgrade — new model can silently break your app
  • A/B test prompts in production to find what actually works with real users
  • Treat evals as CI — run on every prompt change, block merge on regression
