// step 1: gather context

Context is everything.

Before generating a single token, the tool collects as much relevant context as fits in the context window.

01 -- cursor
Current file + position
Code before and after the cursor. The prefix is what you've written; the suffix is what comes next.
02 -- open tabs
Neighboring files
Other open files in your editor. Ranked by similarity to the current file (imports, shared types).
03 -- repo
Project structure
File tree, package.json, tsconfig. Tells the model what framework, language, and patterns you use.
04 -- recent edits
Edit history
What you just changed. If you renamed a variable in file A, the model knows to use the new name in file B.

Key: better context = better suggestions, always

Fill-in-the-middle vs chat.

Inline autocomplete and chat use completely different model architectures and prompting strategies.

// how suggestions get ranked

Not all completions are equal.

The model generates multiple candidates. A scoring pipeline picks the best one to show you.

// simplified suggestion pipeline
const candidates = await model.generate({
  prompt: contextWindow,
  n: 3,              // generate 3 options
  temperature: 0.2,  // low randomness
  stop: ["\n\n"],     // stop at blank line
});

// score each candidate
const scored = candidates.map(c => ({
  text: c,
  logProb: avgLogProbability(c),     // model confidence
  overlap: suffixOverlap(c, suffix), // fits context?
  syntax:  parsesClean(c),           // valid code?
}));

// show the highest scoring one
return topBy(scored, 'logProb');

// the agentic loop

Read, edit, test, repeat.

Modern AI coding tools (Claude Code, Cursor Agent) run a tool-use loop. They're not just predicting tokens -- they're running tools.

step 1
Read files & understand
Agent reads relevant files, searches codebase, looks at error messages. Builds a mental model of the code.
↓
step 2
Plan & edit
Decides which files to change. Makes edits using structured tool calls (not copy-paste). Can edit multiple files.
↓
step 3
Run tests & verify
Executes tests, linters, type checkers. If something fails, loops back to step 1 with the error as new context.
↓
step 4
Iterate until green
Keeps looping until tests pass or max attempts reached. Each iteration uses previous errors to improve.

// the hallucination problem

Why it invents fake APIs.

The model trained on millions of packages. When it can't find the right API, it pattern-matches to something plausible but wrong.

// why it happens
  • Training data is stale Model trained on code from 6-18 months ago. APIs change.
  • Plausible > correct Model predicts likely tokens. db.query.findAll() looks right.
  • Package name confusion Similar packages blur together. Mixes up React Query v4 vs v5 API.
// how to mitigate
  • Include imports in context Open the package's type defs. Model reads actual API.
  • Add examples to prompt "Use this API pattern: ..." beats "use library X".
  • Always run the code TypeScript compiler catches fake methods instantly.

Rule: never trust generated import paths or method names without verifying

// Calculate shipping cost based on weight and zone
// weight in kg, zone is 1-5, returns USD

  // model knows exactly what to write

  ttl: number;
  maxSize: number;
  onEvict?: (key: string) => void;

// tip 3: one example = pattern for the rest

// model generates the remaining test cases

// recap

AI coding tools decoded.

  • Context = open files, cursor position, repo structure, recent edits -- all stuffed into the prompt
  • Inline = fill-in-the-middle model, fast, short completions. Chat = full conversation, complex changes
  • Agentic = read/edit/test loop. Keeps iterating until tests pass. This is the future.
  • Hallucinations = stale training data + pattern matching. Mitigate with types, examples, and verification
  • Better input = better output -- comments, types, and one example go a long way
