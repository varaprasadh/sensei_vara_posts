02 / 08
// issue 1

State leak between turns.

Session memory accidentally shared across users. User B sees User A's context.

// bad — module-level state
shared memory 
// top of agent.py
conversation_history = []

def run_agent(user_msg):
  history.append(user_msg)
  ...
All users share one list. Disaster at 2 concurrent users.
// fix — scoped per session
isolated state 
// per-session context
def run_agent(user_msg, session):
  history = get_session(session)
  history.append(user_msg)
  ...
Session ID → isolated store. Never module-level.
State must live in the request scope, not the module scope. One mutable global poisons every user.

error_cascade.js
03 / 08
// issue 2

Tool errors cascade.

One flaky API → agent retries forever → bill explodes. No circuit breaker, no exit.

// what the loop looks like without guards
while not_done:
  result = call_tool("weather_api")   # flaky — 503s randomly
  if result.error:
    messages.append("tool failed, try again")
    continue                               # ← no retry cap
  process(result)

// result: 80 iterations, $12 for one user query
// symptom
Agent loops on tool error. Bill spikes in silence. No alert fires. You find out on the invoice.
// fix
Return structured error to agent. Hard retry cap per tool. Agent must handle failure, not retry blindly.

// issue 3

"Same input,
different output."

Non-determinism makes bugs unreproducible. You can't fix what you can't replay.

// what makes it non-det
temperature > 0
tool call ordering
  (parallel tools)
wall-clock time in prompts
random UUIDs in context
no request id logged
// how to get reproducibility
temperature = 0 for logic paths
log request_id per call
snapshot inputs + tool results
record seed if any randomness
store full trace, not just output
You can't reproduce the bug if you didn't log the exact inputs + tool results that caused it. Logs are your time machine.

concurrency.js
06 / 08
// issue 5

Concurrency footguns.

Shared mutable tools + parallel tool calls = race conditions. Rare in demo. Constant in prod.

// shared mutable tool state
race condition 
// two agent threads, one cache dict
cache = {}           # shared!

def search_tool(q):
  cache[q] = fetch(q) # not threadsafe
  return cache[q]
Thread A writes while B reads → corrupted result.
// parallel tool execution
ordering undefined 
// model calls 3 tools at once
tools_called: [
  "get_balance",    // reads
  "deduct_funds",   // writes
  "send_receipt"    // reads result
]
// order NOT guaranteed
Write + read in same parallel batch → undefined behavior.
Rule: stateful tools need locks or sequential execution. If tools share state → never parallelize them.

// how to actually debug prod agents

Log everything. Trace every session.

Prompt · tool call · tool result · response. One trace ID per session. No gaps.

trace:a3f9 PROMPT user="book me a flight to NYC" session=u_881
trace:a3f9 TOOL_CALL fn=search_flights args={dest:"NYC", date:"2026-06-01"}
trace:a3f9 TOOL_RES status=200 results=12 latency=310ms
trace:a3f9 RESPONSE tokens_in=1840 tokens_out=280 cost=$0.007
trace:a3f9 TOOL_CALL fn=book_flight args={flight_id:"AA291"}
trace:a3f9 TOOL_ERR status=503 msg="seat unavailable" retry=1/3
Trace ID ties every log line to one session. When prod breaks at 2am you replay the exact trace — not guess.

// the prod agent survival kit

5 things every prod agent needs.

01 — cap
Max iteration cap
Hard limit. Raise intentionally. Prevents runaway loops + infinite bills.
02 — timeout
Per-tool timeouts
Every tool call has a deadline. Flaky API can't hang the whole agent.
03 — state
Isolated session state
Session-scoped memory. Zero module-level mutable state.
04 — logs
Structured trace logs
Prompt + tool call + result + response. Trace ID per session.
05 — kill
Kill switch
Feature flag to disable any tool or the entire agent loop instantly. No redeploy. When prod is on fire you need to kill it in seconds, not minutes.
