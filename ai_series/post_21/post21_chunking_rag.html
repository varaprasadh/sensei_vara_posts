// the core tension

Docs are huge.
Context windows are not.

A 200-page PDF is ~150k tokens. Most context windows fit 8–32k. And even if they fit — you don't want the whole thing.

// your document
150,000 tokens 
Chapter 1: Background ...
Chapter 2: Methods ...
Chapter 3: Results ...
...
Chapter 12: Conclusion
Too big to send every call. Mostly irrelevant noise.
// what you actually need
~500 tokens 
// the 3 relevant passages
retrieve("user query")
  → chunk_42  // 0.94
  → chunk_17  // 0.91
  → chunk_88  // 0.87
Precise context. Model gets signal, not noise.

Chunking is how you get from 150k tokens to 500 — without losing the answer.

fixed.js

// strategy 1

Fixed-size chunking.

Split every N tokens. No questions asked.

// naive fixed split — 512 tokens each
function fixedChunk(text, size = 512) {
  const tokens = tokenize(text);
  const chunks = [];
  for (let i = 0; i < tokens.length; i += size) {
    chunks.push(tokens.slice(i, i + size));
  }
  return chunks;
}
simple fast predictable sizes cuts mid-sentence ignores meaning

Good baseline. Terrible for coherence. Use it to prototype, not to ship.

sentence.js
04 / 08
// strategy 2

Sentence & paragraph chunking.

Split at natural boundaries. Each chunk is a complete thought.

sentence-level
Split on "." "!" "?"
Fine-grained. Each chunk is one idea. Sizes vary from 10 to 80 tokens.
paragraph-level
Split on "\n\n"
More context per chunk. A paragraph is usually one concept. Sizes vary 50–300 tokens.
pros
Respects structure
No mid-sentence cuts. Chunks feel natural. Embeddings capture whole thoughts.
cons
Variable sizes
One chunk = 12 tokens. Next = 300. Hard to predict retrieval behaviour at scale.

// strategy 3 — the workhorse

Recursive chunking.

Try big separators first. Fall back to smaller ones. Respects hierarchy.

## Headers // try first
↳ \n\n paragraphs // then
↳ \n sentences // then
↳ " " words // last resort
// LangChain RecursiveCharacterTextSplitter
const splitter = new RecursiveCharacterTextSplitter({
  chunkSize:    512,   // max tokens per chunk
  chunkOverlap: 50,    // overlap window
  separators:   ["\n## ", "\n\n", "\n", " ", ""],
});

Best general-purpose strategy. Works on markdown, PDFs, code.

10–20% overlap saves context.

The answer is often at the seam between two chunks. Overlap makes sure you don't miss it.
