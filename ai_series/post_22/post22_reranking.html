similarity.js

// what vector search actually does

Similar ≠ correct answer.

Vector search ranks by cosine similarity. It finds vectors that point in the same direction. That's it.

// what the retriever computes
score(query, doc) = cosine_similarity(
  embed(query),
  embed(doc)
)

// what it does NOT compute
// "does this doc answer the query?"

"Similar" means overlapping embedding space — not factual relevance.

// the fix: two stages

Cheap retrieve, expensive rerank.

Stage 1 casts wide. Stage 2 picks precisely. You pay for precision only where it matters.

// input
query
user's question
→
// stage 1
retrieve top-K
vector search
K = 50 docs
fast, cheap
→
// stage 2
rerank top-N
score each pair
N = 5 docs
slow, accurate
→
// output
send to LLM
top 5 only

Retrieve K=50 so recall is high. Rerank to N=5 so precision is high. LLM only sees the 5.

encoder.js
05 / 08
// how the reranker works

Bi-encoder vs cross-encoder.

bi-encoder
fast
Embeds query and doc independently. Compare vectors at query time. Pre-index everything.
+ scales to millions of docs
− no cross-attention between query & doc
cross-encoder
accurate
Feeds [query + doc] jointly to the model. Score = direct relevance judgment.
+ full attention across both texts
− can't pre-index; scores one pair at a time

Use bi-encoder to find candidates fast. Use cross-encoder to sort them accurately.

cost.js

// the trade-off

Worth it when recall hurts.

A reranker adds latency and cost. It's a deliberate trade, not a free upgrade.

latency
+30–100ms
Scoring 50 docs sequentially. Runs after retrieval, before generation.
cost
per search call
~$0.001–0.004 per query at Cohere/Voyage scale. Adds up at high QPS.
benefit
precision lift
Typical +10–25% NDCG vs vector-only. Biggest gains on ambiguous queries.
skip it when
low ambiguity
Highly specific domain, short queries, or if you already filter by metadata first.

08 / 08
// the decision rule

Add a reranker when.

  • Retrieval finds the right doc but the model still gets it wrong — wrong chunk surfaced first
  • Your top-1 result ≠ the best answer — reranker re-sorts the list
  • Queries are naturally ambiguous — proper nouns, acronyms, multi-domain corpora
  • You're already retrieving K ≥ 20 — wide recall + tight precision is the whole point
retrieval ≠ relevance. retrieval + reranking ≈ relevance.
