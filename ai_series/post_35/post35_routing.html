// pattern 1

Classifier-based routing.

A small, fast model classifies the query complexity, then routes to the right tier.

step 1
Classify
Tiny model (or fine-tuned classifier) tags query as simple / medium / complex. Costs ~0.001 cents.
↓
step 2
Route
Simple → Haiku. Medium → Sonnet. Complex → Opus. Each tier costs 3-5x more than the one below.
↓
step 3
Respond
Selected model handles the query. User gets same quality at a fraction of the cost.

Key: the classifier is cheap and fast — adds <50ms latency.

// pattern 2

The cascade pattern.

Try the cheapest model first. If it's not confident, escalate. No classifier needed — the model self-reports uncertainty.

async function cascade(query) {
  // try cheapest first
  const fast = await callHaiku(query);

  if (fast.confidence > 0.85) {
    return fast.answer;  // done — saved 90%
  }

  // uncertain → escalate to mid-tier
  const mid = await callSonnet(query);

  if (mid.confidence > 0.85) {
    return mid.answer;
  }

  // still uncertain → bring in the big model
  return (await callOpus(query)).answer;
}

Tradeoff: higher latency on hard queries (serial calls), but zero wasted spend on easy ones.

// build your own

A simple router.

Classify with Haiku, route to the right model. 15 lines of code, 10x cost savings.

const MODELS = {
  simple:  "claude-haiku",
  medium:  "claude-sonnet",
  complex: "claude-opus",
};

async function route(query) {
  // step 1: classify with cheapest model
  const { tier } = await callHaiku({
    system: "Classify query complexity as: simple, medium, complex. Return JSON.",
    prompt: query,
  });

  // step 2: route to the right brain
  return callModel(MODELS[tier], query);
}

Production tip: log tier decisions — you'll discover your classifier miscategorizes ~5% of queries. Fix those with examples.

// choosing a strategy

Classifier vs cascade.

Both save money. Pick based on your constraints.

// classifier routing
  • Lowest latency (one classification + one call) Best for real-time apps where speed matters.
  • Predictable cost per query Always exactly 2 API calls.
  • Needs training data You need labeled examples to build a good classifier.
// cascade routing
  • No training data needed Model self-reports confidence. Works out of the box.
  • Cheapest on easy queries Only 1 call when the small model is confident.
  • Higher latency on hard queries Worst case: 3 serial calls before getting an answer.

Hybrid approach: classifier for known patterns, cascade for everything else
