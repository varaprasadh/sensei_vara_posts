// the fix

Cache the prefix.

The provider stores the prefix of your prompt after the first call. Next call hits the cache instead of re-processing.

1st call → write prefix → cached ✓
2nd call → read cached prefix → cheaper + faster TTFT

First call seeds the cache. Every call after sips from it.

06 / 08
// the trap

Never the tail.

Anything that changes between calls poisons the prefix. Cache miss every time.

  • user input — different every turn, by definition
  • live timestamps — stamping Date.now() into the system prompt invalidates the cache constantly
  • per-user variables — names, IDs, prefs inlined into what should be the stable prefix → defeat caching
  • chat history — unless you pin a stable summary at the cache boundary

Order matters. Stable stuff first. Volatile stuff last.
