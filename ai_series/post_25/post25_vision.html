// use case 02 — image → typed data

Structured extraction.

Image + schema prompt → typed JSON out. One pattern fits receipts, forms, business cards, invoices.

// the pattern
const result = await client.messages.create({
  model: "claude-opus-4-5",
  messages: [{
    role: "user",
    content: [
      { type: "image", source: { type: "base64", data: imgB64 } },
      { type: "text", text: `Extract as JSON: { vendor, date, total, items[] }` }
    ]
  }]
});

// output you can parse directly
// { vendor: "Whole Foods", date: "2026-05-20",
//   total: 47.82, items: [{name, qty, price}] }

Schema in prompt = typed contract. Combine with JSON mode for zero parse errors.

limits.js
07 / 08
// where it breaks

What vision-LLMs can't do.

Knowing the failure modes saves you from shipping a broken product.

// small text
Fine detail in high-res
6pt footnote text in a 300dpi PDF? The model often misreads or skips it. Patch size ≠ pixel-perfect.
// counting
Literally bad at counting
"How many people in this photo?" is unreliable past ~5. Token patches don't map 1:1 to objects.
// coordinates
Spatial reasoning
"Top-left element" or exact pixel coords are guesses. Don't trust bounding box output for automation.

Need precision? Pair with classical CV (YOLO, CLIP, pytesseract) — don't replace it.
